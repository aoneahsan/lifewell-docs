# 紹介プログラム

紹介コードを受け取り、相手がそのコードで登録します。その登録が**確認されると**ポイントとバッジが付き、基準に達すると有料プランが1か月延長されます。

## 確認済みの意味

確認はリンクのクリックではありません。招待されたアカウントが存在し、**メールアドレスも確認済み**である必要があります。両方が成立した時点でサーバーが判断します。

有料プランを付与する経路なので、この条件を厳密にしています。クリックだけで付与すれば、リンクを開くことに対価を払う制度になってしまいます。

## データベースが守る規則

- **1人が紹介されるのは1度だけです。** アカウントを削除して作り直しても、特典は増えません。
- **自分を紹介することはできません。** フォームにも表示され、最終的にはデータベースが判断します。
- **付与を確定する処理をブラウザーから直接呼べません。** 利用者が*自分を確認*できれば、*自分に有料特典を付与*することもできてしまいます。

## 招待した相手について見えること

件数と状態だけです。名前は表示されません。

紹介者に招待された人の一覧を見せないという約束は、画面で隠すだけではありません。許可されたクエリは、その人の識別子自体を返しません。

## 置き換えずに延長する1か月

既に有料プランを持っているときに特典が届いた場合、その1か月は現在の期間の末尾に加わります。支払い済みの期間を上書きしません。

## 数値はすべて管理画面の設定

確認済みの登録1件あたりのポイント、バッジ、基準、付与する月数、対象プラン、月ごとの上限は、コードに固定せずシステム設定として管理します。リリースなしで変更でき、表示される文章も現在の設定から作られます。

具体的な基準と上限は、ログインしたアカウントにだけ表示されます。不正な紹介を繰り返そうとする人にとって、最も知りたい数字でもあるためです。

## 現在の状態

:::warning[利用者向けの画面はまだありません]
サーバー側の台帳、確認処理、付与、有料プランを延長する特典、7つの数値を扱う管理機能は稼働しています。**まだないのは、自分のコードと件数を表示する画面です。** 完成するまで、アプリ内に開ける場所はありません。
:::

画面が完成した後は、招待とその特典が[エクスポート](../reference/export-format.md)に**招待した人**と**招待から得たもの**として含まれます。
