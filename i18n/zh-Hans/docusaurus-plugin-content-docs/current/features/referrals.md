# 推荐计划

您会获得一个邀请码。有人使用它注册，且注册**得到确认**后，您会获得积分和徽章；达到门槛后，还会获得一个月的付费方案。

## 什么叫“得到确认”

确认依据是真实注册，不是点击链接：受邀账号必须**已经建立**，并且邮箱地址**已经验证**。两项条件都满足时，由服务器作出判断。

之所以严格，是因为确认流程会授予付费方案。如果只要点击就发放奖励，打开链接就能换取付费权益。

## 数据库执行的规则

- **同一个人只能被推荐一次。** 删除账号后重新注册，不能借此重复获得奖励。
- **不能推荐自己。** 表单会提示您，数据库也会执行这条规则。
- **浏览器不能直接调用发奖流程。** 如果客户端能自行调用“确认我”，就等于能自行要求“给我奖励”。

## 您能看到受邀者的什么信息

只有人数和状态，没有姓名。

推荐者不会看到逐一列出的受邀者。这项限制由列级授权保证，不只是页面选择不显示：您有权执行的查询根本不会返回身份标识。

## 奖励月份会延长现有方案

如果奖励到达时您已经订阅付费方案，新增的一个月会接在现有期限之后，不会覆盖您已付款购买的时间。

## 所有数值都由管理员设置

每次确认注册所得积分、徽章、门槛、奖励月份、对应方案和每月上限，均为平台设置，不是代码中的常量。无需发布新版本即可调整。您读到的具体说明会根据当前设置生成。

准确门槛和上限只对已登录账号显示。这些数字正是试图滥用推荐计划的人想知道的。

## 目前进度

计划的服务端部分已经上线：记录台账、确认流程、奖励发放、延长付费方案的奖励，以及管理员对七项数值的控制。**还没有建成的是显示您邀请码和人数的页面。** 在页面完成前，应用内没有可供您打开的入口。
