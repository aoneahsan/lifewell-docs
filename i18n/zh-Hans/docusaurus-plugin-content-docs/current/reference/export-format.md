# 导出文件格式

这里说明[导出副本](../your-data/export.md)生成的文件，让其他应用不必猜测，就能读懂它。

这不是 LifeWell 专有格式。JSON 就是普通 JSON，压缩包也只是普通 CSV 文件组成的 ZIP。

## 三种文件

| 格式 | 文件名 | 媒体类型 | 范围 |
|---|---|---|---|
| JSON | `lifewell-export-<YYYY-MM-DD>.json` | `application/json` | 所选日期范围；每张表最多 5,000 行 |
| CSV | `lifewell-export-<YYYY-MM-DD>.zip` | `application/zip` | 所选日期范围；每张表最多 5,000 行 |
| PDF | `lifewell-export-<YYYY-MM-DD>.pdf` | `application/pdf` | 摘要——见下文 |

日期取自您设备上的当地日期，不取服务器日期。文件名在所有语言中都保持 ASCII 字符和相同结构，方便您日后在下载文件夹中搜索。

## JSON 文档

整个文件是一个对象：先是简短的文件头，再以每张表的名称为键，各自保存一组行。

```json
{
  "exportedAt": "2026-09-08T11:04:22.417Z",
  "schema": 1,
  "range": { "from": "2026-01-01", "to": "2026-09-08" },
  "rowCap": 5000,
  "truncated": ["metric_entries"],
  "profile": { "id": "…", "display_name": "…" },
  "conditions": [],
  "medications": [ { "…": "…" } ]
}
```

| 文件头字段 | 类型 | 含义 |
|---|---|---|
| `exportedAt` | ISO 8601 字符串，UTC | 文件生成时间 |
| `schema` | 数字 | 格式版本，目前为 **1** |
| `range.from` / `range.to` | ISO 日期或 `null` | 您选择的时间范围；`null` 表示不设边界 |
| `rowCap` | 数字 | 每张表适用的行数上限——**5000** |
| `truncated` | 表名数组 | 达到行数上限的表；空数组表示没有截断 |
| `profile` | 对象或 `null` | 您的个人资料行，直接保存为对象，而不是只有一项的数组 |

编写读取程序前，值得知道三点：

- **没有记录的表仍是空数组，不会缺少键。** `"meals": []` 表明这张表为空；缺少 `meals` 键则会让人不知道发生了什么。
- **`truncated` 是文件不完整的唯一信号。** 在断定某人没有历史记录前，先看这个字段。
- **JSON 使用两个空格缩进。** 这份文件本来就应供您打开和搜索；八兆字节挤成一行，文本编辑器很难顺利查看。

## CSV 压缩包

ZIP 中**每张表各有一个 `.csv` 文件**，命名为 `<table>.csv`。列名使用对应数据库表自己的列名。

| 细节 | 值 |
|---|---|
| 换行 | 按 RFC 4180 使用 CRLF |
| 编码 | 带**字节顺序标记**的 UTF-8 |
| 引号 | 遵循 RFC 4180：引号成对转义；包含 `"`、`,`、CR 或 LF 的字段加引号 |
| 空单元格 | `null` 与 `undefined` 都转换为空单元格 |
| 嵌套值 | 在单元格中保留为完整 JSON，不拆成多行 |

还有两项有意设计，若不知道，可能看起来像错误：

- **即使表中没有行，也会生成对应文件**，只含表头。缺少文件和导出失败难以区分；只有表头也能证明系统处理过该表。
- **以 `=`、`+`、`-`、`@`、制表符或回车开头的单元格文本，会加上一个前置单引号。** 电子表格可能把这些字符当成公式。您的记录属于您；这项处理是为拿到文件的人着想——本页讨论的接收者常是医生。若您用程序解析，而不是在电子表格中打开，可以移除前置单引号。

字节顺序标记的原因是：Windows 版 Excel 可能把没有标记的 UTF-8 文件当作本地编码读取，结果把带重音符号的人名显示错。这个格式存在，就是为了让人能读懂文件。

## 文件中的每张表

共六十五张表，按所属领域分组。

- **日期范围**——*带日期的记录*遵守您选择的时间窗口；*长期有效的记录*总会包含在内，因为只有服药记录、没有对应药物，看起来像数据丢失。
- **PDF 中的形式**——*完整列出*会打印各行；*仅计数*只打印数量和时间跨度，不列出记录；*不进入 PDF* 就是不包含。

## 各格式省略什么 \{#what-each-format-leaves-out}

**JSON 和 CSV 包含所选日期范围内受支持的表格。** 范围以外的带日期记录会被省略；任何超过 5,000 行的表都会截断，并在文件头中列明。这些格式可用于阅读或转移已包含的数据；LifeWell 目前不能从这些文件恢复账号。

**PDF 不完整，而且这是它的用途所决定的。** PDF 常被打印、交给前台，再放在桌上。因此，它只包含临床医护人员实际需要看的内容：

- **完整列出**——长期有效的记录：健康状况、药物、指标类型和目标、孩子、生长测量、成长节点、人物、连接、分享、日历、提醒和您的个人资料。
- **仅计数**——数量较多的带日期记录：指标读数、服药、餐食、运动、周期日期、婴儿记录、引导练习、媒体文件和收藏地点。四千条里只列四十条，是抽样；若一份名为*您的记录*的文件只含抽样，会误导收件人。完整列出的表最多打印 **60 行**。
- **完全不进入 PDF**——日记、回忆、笔记、剪贴簿、消息、社区回复，以及其他供个人保存的内容。

:::warning[日记绝不会进入 PDF，这不是偏好设置]
本页其他取舍大多关乎什么内容有用。日记则是 LifeWell 中唯一绝不能印在一张可能被人放在桌上的纸上的内容。它会进入您自行打开的 JSON 和 CSV 文件。
:::

## 所有格式都不包含什么

有七类内容**绝不会**进入导出文件。所选日期范围和每表行数上限还可能排除更多条目。

| 不包含的内容 | 原因 |
|---|---|
| **媒体文件本身** | 图片在您自己的 Google Drive 中。导出文件包含引用、说明和日期；文件字节从不由我们持有，也就无法由我们交付 |
| **别人分享*给您*的内容** | 那是别人的记录，只是借您查看。对方撤销后您便不能再看；若留在您的导出文件中，就无法撤回 |
| **已删除的行** | 删除就是删除。导出功能背后没有回收站 |
| **运行日志** | 速率限制计数、已关闭的提示等属于界面状态，不是您的生活记录 |
| **您的密码** | 并不存在密码。使用 Google 登录，我们不会看到或保存密码 |
| **您的 AI 服务商密钥** | 它经过加密保存，是仍有效的凭据。把它写进您可能发邮件传送的纯文本文件，只会造成泄露 |
| **AI 用量计量** | 这是计算额度的计量值，不是您写下的内容 |

另有五张表因同类原因保留在系统中，不进入导出：它们保存的是凭据或其他人的记录。

| 保留不导出的内容 | 原因 |
|---|---|
| 您对帖子作出的举报 | 包括您自己在内，任何人都不能读回举报表。若审核队列能从下载文件中泄露，只是多绕一步而已 |
| 献血者披露的联系方式 | 只向一人披露一次，而且可以撤回。下载文件中的一行不具备这两种限制 |
| 您的 Google Drive 连接 | 其中包含仍有效的刷新令牌 |
| Google Play 购买记录 | 其中包含 Google 会接受的购买令牌。您的使用权益已经在导出文件的个人资料中 |
| 已关闭的公告 | 记录的是您关闭过哪些通知，属于界面状态 |

另有四张表是共用参考资料，不属于您个人：方案清单、社区小组目录、食物数据库，以及一张用于存活检查的内部表。

## 重新读取

LifeWell 没有导入功能，不会读取其中任何一种文件并恢复记录。

文档说明格式，是为了让**其他工具**能够读取：脚本、电子表格、其他应用，或五年后拿着文本编辑器的您。有两点让这件事实际可行，而且都是有意设计：

1. 文件中的每个标识符都使用数据库本身的列名，因此同一列在 JSON、CSV 和本页中含义一致。
2. 文件头会说明自身限制。不完整的文件会在前十行直接写明不完整。

## 本页何时更新

每次新增表，都会在上面增加对应行；一项测试会双向核对这里的清单与数据库结构。任何一边多出表，构建都会失败，而不是悄悄发布缺少说明的文件。

如果您正在编写读取程序，请以 `schema` 字段判断格式。目前值为 `1`；上述结构中任何内容的含义改变前，该值都会先增加。
