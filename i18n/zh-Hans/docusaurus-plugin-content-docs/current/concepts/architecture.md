# 架构

LifeWell 是**静态单页应用**。构建产物是一个文件夹，部署的全部内容就在其中。整个结构中没有 Node 服务器。

## 系统结构

```text
浏览器 / Android WebView
        │
        ├──────────────► 通过 PostgREST 访问 Postgres      （普通读写）
        │                 · 行级安全
        │                 · 列级授权
        │                 · 列表最多 50 行
        │
        └──────────────► 运行在 Deno 上的边缘函数        （浏览器不能持有的内容）
                          · 经机器人检查的两种公开表单
                          · 解析只读分享链接
                          · 交换 Google Drive 令牌
                          · AI 费用估算及您自己的 AI 密钥
                          · 定时导出
                          · Play 购买验证
                          · 管理员操作
```

## 如何决定使用哪条路径

> 普通数据由浏览器直接与数据库交互。只有操作需要浏览器**绝不能持有**的内容时，才使用边缘函数——例如密钥、更高权限，或需要验证用户输入。

其他操作都是以您的身份直接查询，并遵守[隐私与安全](./privacy-and-security.md)中说明的规则。

## 为什么把权限边界放在数据库中

如果授权只存在于应用代码里，每个调用位置都要记得执行它。行级安全让*数据库*自行拒绝越权访问：即使查询写错，也只会返回空结果，而不是别人的记录。

这也是正在运行的应用不使用 ORM 的原因。数据库结构在 TypeScript 中编写，并在线下生成迁移文件；但应用运行时，只通过客户端库以当前登录者的身份访问数据库，由数据库规则负责限制。

## 使用的技术

| 层 | 选择 |
|---|---|
| 框架 | React 19 |
| 构建 | Vite 8，生产环境不生成源码映射 |
| 路由 | 文件式路由，搜索参数有类型约束 |
| 服务器数据状态 | TanStack Query |
| 客户端状态 | Zustand，不用 React context 管理应用状态 |
| 表单 | React Hook Form 和 Zod；边缘函数也使用相同的 Zod 结构验证 |
| 无障碍支持 | React Aria Components 负责控件的 DOM、ARIA 标记和键盘行为 |
| 样式 | Tailwind v4，在 CSS 中配置，而非使用配置文件 |
| 图表 | D3 |
| 富文本 | Tiptap；产品中没有普通纯文本输入框 |
| 本地存储 | 只允许一个库接触浏览器存储 |
| Android | Capacitor 8 |

## 不再使用 Firebase

2.x 应用运行在 Firebase 上。重建要解决的问题之一，就是它曾耗尽免费方案的读取额度，让真实用户在额度重置前整整一天无法使用。

分享模式也是另一个原因。向指定的人分享记录的一部分，是行级权限问题。Postgres 在数据库中解决；旧文档数据库则靠规则文件回答，规则必须与每项查询保持同步。

## 地址中的界面状态

弹窗、标签页、筛选、排序、分页和搜索词都保存在地址栏中，而非组件内部状态。刷新页面不会丢失您所在的位置；分享当前页面链接时，对方打开的也正是您看到的状态。
