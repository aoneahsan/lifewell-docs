# Архитектура

Это **статическое одностраничное приложение**. Сборка создаёт каталог файлов, который целиком публикуется на сайте. Отдельного сервера Node здесь нет.

## Общая схема

```text
Браузер / Android WebView
        │
        ├──────────────► Postgres через PostgREST          (обычное чтение и запись)
        │                 · защита на уровне строк
        │                 · права доступа к столбцам
        │                 · строгий предел 50 строк в списке
        │
        └──────────────► Периферийные функции на Deno      (только то, что нельзя доверить браузеру)
                          · две публичные формы с проверкой на бота
                          · открытие ссылки для чтения
                          · обмен токена Google Drive
                          · оценочный запрос ИИ и ваш собственный ключ ИИ
                          · экспорт по расписанию
                          · проверка покупки Play
                          · административные действия с учётной записью
```

## Правило выбора пути

> Для обычных данных браузер обращается прямо к базе. Периферийная функция используется **только** тогда,
> когда операции нужен секрет, повышенное право или проверка сведений, введённых человеком, которые нельзя
> доверить браузеру.

Остальные запросы выполняются напрямую от вашего имени по правилам, описанным в разделе [Конфиденциальность и безопасность](./privacy-and-security.md).

## Почему защита находится в базе данных

Если разрешения проверяет код приложения, каждый вызов должен не забыть об этой проверке. При защите на уровне строк решение принимает *база данных*: ошибочный запрос вернёт пустой результат, а не чужие записи.

По этой же причине работающее приложение не использует ORM. Схема описывается в TypeScript и превращается в миграции вне приложения. Само приложение обращается к базе только через клиентскую библиотеку от имени вошедшего человека, с действием тех же правил.

## Используемые технологии

| Слой | Решение |
|---|---|
| Интерфейс | React 19 |
| Сборка | Vite 8, без карт исходного кода в рабочей версии |
| Маршруты | Файловые маршруты с типизированными параметрами поиска |
| Данные сервера | TanStack Query |
| Состояние клиента | Zustand; React context не используется для состояния приложения |
| Формы | React Hook Form и Zod; те же схемы Zod проверяют запросы периферийных функций |
| Доступность | React Aria Components обеспечивает DOM, ARIA и работу элементов с клавиатуры |
| Оформление | Tailwind v4 с настройкой в CSS, без отдельного конфигурационного файла |
| Диаграммы | D3 |
| Оформленный текст | Tiptap; обычного текстового поля без оформления в продукте нет |
| Локальное хранение | Одна библиотека, единственная с правом обращаться к хранилищу браузера |
| Android | Capacitor 8 |

## Почему не Firebase

Версия 2.x работала на Firebase. Один из поводов для перестройки — исчерпание бесплатного лимита чтений, из-за которого приложение не работало один день.

Вторая причина — устройство общего доступа. Разрешение читать часть журнала конкретному человеку решается для отдельных строк. Postgres проверяет его в базе; прежнее документное хранилище опиралось на файл правил, который приходилось согласовывать с каждым запросом.

## Состояние в адресе страницы

Открытые окна, вкладки, фильтры, сортировка, страницы списков и поисковые фразы хранятся в адресе, а не только в состоянии компонента. После обновления страницы вы остаётесь на нужном месте; ссылка ведёт именно к тому, что вы смотрели.
