# API LifeWell

REST API LifeWell работает по одному базовому адресу. Все маршруты, поля и ошибки описаны в машиночитаемом файле OpenAPI. Именно он, а не эта страница, служит полным справочником. Здесь объясняется, где его найти, как читать и каким двум правилам подчиняется каждый список.

## Какой базовый адрес?

```text
https://mednqghfhaazsikbmtiz.supabase.co/functions/v1/api/v1
```

Последнее `v1` — версия API. Для каждого запроса нужен токен или подключение приложения. См. [Авторизация](./authentication.md).

```bash
curl -H "Authorization: Bearer $LIFEWELL_TOKEN" \
  https://mednqghfhaazsikbmtiz.supabase.co/functions/v1/api/v1/openapi.json
```

## Где полный справочник?

| Файл | Адрес | Чем читать |
|---|---|---|
| OpenAPI 3.1, JSON | [`/v1/openapi.json`](https://mednqghfhaazsikbmtiz.supabase.co/functions/v1/api/v1/openapi.json) | Любой инструмент OpenAPI: Swagger UI, Redocly, Postman, Insomnia или генератор клиента |
| Те же сведения в Markdown | [`/v1/openapi.md`](https://mednqghfhaazsikbmtiz.supabase.co/functions/v1/api/v1/openapi.md) | Браузер, текстовый редактор или ИИ-помощник, которому вы вставите текст |

Оба файла создаются из того же источника, что и API. Поэтому они не могут описать отсутствующий маршрут или пропустить существующий. Отдельные страницы для ресурсов на этом сайте будут создаваться из того же файла; пока подробности находятся в нём.

## Как читать файл OpenAPI?

Чаще всего нужны четыре части:

- **`paths`** — маршруты, их методы и необходимые области доступа.
- **`components.schemas`** — все возможные поля ответа и их типы. Поле, которого здесь нет, не отправляется.
- **`components.securitySchemes`** — два способа входа: токен доступа Bearer и OAuth.
- **Ответы с ошибкой** — коды `code` из [формата ошибки](./authentication.md#как-выглядит-ошибка) для каждого маршрута.

API открывает ровно те разделы журнала и поля, которые перечислены в файле. Отсутствующее поле намеренно недоступно.

## Как работает загрузка по страницам?

Каждый список разделён на страницы:

- По умолчанию **20 строк**, не более **50**.
- Если после страницы есть следующая, ответ содержит `next_cursor`. Передайте это значение в новом запросе.
- Если `next_cursor` отсутствует, страница последняя.

Курсор — закладка, а не номер страницы. Поэтому строка, добавленная во время чтения, не сдвинет все последующие результаты на одну позицию. Названия параметров размера и курсора указаны для каждого маршрута списка в OpenAPI.
