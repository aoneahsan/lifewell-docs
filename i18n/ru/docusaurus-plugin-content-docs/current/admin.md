# Панель администратора

`/admin`. Участники LifeWell этой частью продукта не пользуются. Но её стоит описать: здесь задаются пределы планов и результаты модерации, а также видно, какие сведения администратор может и не может узнать об учётной записи.

## Три роли

| Роль | Доступ |
|---|---|
| **Модератор** | Очередь жалоб только для чтения и списки сотрудников |
| **Администратор** | Всё перечисленное ниже |
| **Главный администратор** | То же самое, плюс назначение ролей |

Чтение очереди жалоб и принятие решений — **намеренно разные права**. Модератор может работать с очередью, но не решать исход жалобы. Иначе при добавлении роли она сразу получила бы власть скрывать чужие публикации без отдельной проверки этого права.

## Десять экранов

| Экран | Назначение |
|---|---|
| `/admin` | Обзор |
| `/admin/users` | Список учётных записей, назначение и отзыв роли, приостановка и восстановление доступа, удаление, индивидуальное изменение пределов |
| `/admin/plans` | Создание, изменение и закрытие уровня; разбор заявления об оплате; назначение плана со сроком; способы оплаты; соответствие товаров Play; покупки устройства |
| `/admin/moderation` | Очередь жалоб и решение по каждой |
| `/admin/verifications` | Проверки специалистов по реестрам: одобрить или отказать |
| `/admin/inbox` | Сообщения из формы участия |
| `/admin/announcements` | Подготовка, публикация и завершение объявлений, включая сообщения о других продуктах |
| `/admin/content` | Каталог самочувствия и системные виды показателей |
| `/admin/settings` | Настройки платформы, режим обслуживания, флаги функций, два переключателя оплаты, значения реферальной программы, адрес для связи |
| `/admin/audit` | Журнал действий |

Все тридцать две административные операции за этими экранами отказывают обычному пользователю. Это проверено запуском каждой операции от учётной записи без административной роли, а не только чтением кода.

## Чего администратор не видит

**Ваш журнал.** Список учётных записей и их подробности возвращают только разрешённые столбцы; сведений о здоровье в них нет. Управлять учётной записью не значит читать личный дневник.

Есть ещё два намеренных ограничения:

- **Токен покупки Play и полный чек** недоступны панели. Первый служит ключом для обращения к Google, второй содержит весь документ о покупке. Для ответа на вопрос о сроке плана ни то ни другое не нужно.
- **Список приглашений нельзя просмотреть целиком.** Политика чтения открывает человеку только собственные строки, поэтому администратор не может листать приглашения. Это реальное ограничение: заметить цепочку фиктивных приглашений через панель сейчас нельзя.

## Журнал аудита

`/admin/audit`. Строки добавляют **только серверные функции**, выполняющие действие. Прав на прямое добавление, изменение или удаление нет ни у кого. Если участник может сам записать строку, он может подделать журнал; если может стереть — журнал перестаёт быть надёжным.

Отсюда следуют два правила:

- При удалении учётной записи строка аудита записывается **сначала**. Если запись не удалась, удаление не выполняется.
- Строки аудита остаются после удаления учётной записи. Они называют действие, а не содержимое журнала человека.

## Действия панели, которые замечает участник

- **Пределы планов хранятся в строках, а не в коде.** Предел можно изменить без выпуска приложения, а новый уровень добавить одной строкой. Панель не сохранит платный уровень хуже Free; проверка выполняется базой данных в той же транзакции.
- **У назначенного плана есть дата окончания и причина.** Назначение плана с уже прошедшим сроком отклоняется: он не появился бы на экранах и не показал бы ошибку.
- **К решению по жалобе прилагается пояснение.** Автор видит один вариант, пожаловавшийся человек — другой.
- **При проверке специалиста указывается реестр**, по которому её провели. Заявку без названия реестра можно только отклонить.
- **Индивидуальное изменение предела сопровождается пояснением.** Если причину нельзя узнать, изменение трудно отменить.

## Два переключателя с ограниченным действием

О них стоит сказать прямо:

- **Выключенный флаг функции не запрещает запись.** Он скрывает пункт меню и экран. Это настройка вида, а не защита данных.
- **Режим обслуживания предупреждает, но не закрывает доступ.** Он меняет экран продукта, но не отключает базу данных.

## Действие без экрана

Отмена реферальной награды выполняется серверной функцией без интерфейса, поэтому её вызывают напрямую через базу данных. Без причины функция отказывает: отмену должно быть возможно объяснить.
